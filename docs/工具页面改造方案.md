> 版本:v0.116.10 基线 | 审查方式:5 路并行代码审查(全部工具页逐行通读 + 后端命令面/ACL/sidecar 三层取证),所有结论均有 `文件:行号` 证据

## 0. 总体结论

工具页整体「能连、能看、能基本操作」,但存在四个系统性问题:

### ① 后端能力明显领先前端,大量已建成能力零接线(最高性价比缺口)

后端(Rust command + ACL + Go sidecar)三层就绪但前端零调用的能力:

### ③ 右键菜单:覆盖率约 1/3,且两套实现并存

**已覆盖**(共享 `ContextMenu` 组件,`CN/ContextMenu.tsx`):资产行、文件树节点/搜索行、DB 库行、DB 表行、数据网格行。
**SFTP 自绘一套**(fixed 定位 + 手算视口夹紧,无 role="menu"、无键盘),未用共享组件:`CN/terminal/SftpPanel.tsx:516-548`。
**零覆盖**:SSH 终端(选中复制/粘贴/清屏/重连)、Redis(db 节点/key/文件夹)、ES(索引行/命中行/映射字段)、Docker(容器行/镜像行)、Broker(topic 行/卡片)、沙箱实例卡、Android 设备卡、执行记录行、数据网格单元格与列头、DB 列节点、查询标签、面包屑、传输任务行。

共享组件本身的能力缺口:`Menu` 原语支持 footer/selectedId/align/side/dense/compact/label 组标题/子菜单,包装层全部不透传(`CN/ContextMenu.tsx:64-72`);MenuItem 无快捷键提示字段;无 `aria-haspopup/aria-expanded`、无焦点管理、无 Shift+F10 键盘入口;「点击后保持打开」语义缺失(资产行靠 1.5s 定时器伪造「已复制」)。

### ④ 交互一致性债:「一个事实多处编码」

- **危险确认 3 套并存**:两段式按钮(删连接)/ 专用确认弹窗(SFTP)/ 无确认(沙箱销毁、执行记录清空、ExecRecordList 断开、文件覆盖保存)
- **原生 `window.confirm/alert` 散落各处**(DB 删表/清空表/导出成功、Redis 删 key/FLUSHDB、Docker 删容器/删镜像/prune),与设计系统弹层不一致
- **错误呈现 4 套**:`status+retryButton` / `errorBanner` / `statusLineError` / `bannerError`,各模块自定
- **预览态检测 4 种写法**:store `preview` / 直读 `__TAURI_INTERNALS__` / 按错误文案 includes 匹配 / 混为普通错误
- **加载态**:多处整块替换为「加载…」导致列表闪没(资产列表、Docker 容器/镜像);子类切换无脑重拉
- **键盘/Esc**:工具面板无 Esc 关闭无焦点陷阱(它是 `aria-modal` dialog);沙箱两个自研弹窗无 Esc;DB 三个对话框无 Esc;Docker 日志弹层无 Esc;而 StarHubOverlay/连接卡有 —— 同产品两套习惯
- **死代码/漂移**:`terminal/WebBrowser.tsx` 整组件无生产挂载(生产走 Rust 壳页,两套 postMessage 协议互不匹配);`exportError` 死状态(DbWorkbench);`redisInfo`/`esCount`/`indexRowOf` 死封装;`assetWindowUrl` 重复死分支(`CN/sections.ts:189-192`);Redis Dashboard 分支不可达;`sandbox/android` 特判三处编码

## 1. 横向改造(先做地基,后续每页收益)

### 1.1 建设 StarHub 共享 UI 原语层(目前只有 ContextMenu 一个胶水组件)

新增/增强 `CN/components/`(名字示意):

1. **`ContextMenu` 增强**:透传 footer/align/side/dense/compact;支持 label 组标题与子菜单样板;MenuItem 加 `shortcut` 提示字段;补 `aria-haspopup/aria-expanded`、打开移焦/关闭还焦、Shift+F10 键盘入口、「⋮」备用触发钮;统一「一个面板一个菜单实例 + target 状态」范式(资产行现在每行一个 Menu portal)。**SFTP 自研菜单迁移过来,消灭第二套实现**。
2. **`ConfirmDialog`**:统一危险确认(两段式 + 弹窗二合一),支持输入名称二次确认(用于 FLUSHDB/删索引/销毁沙箱)。替换全部 `window.confirm/alert`。
3. **`StatusBanner` / `EmptyState` / `LoadingBlock`**:统一错误(可关闭、带重试)、空态(带 CTA)、加载(骨架/spinner)四套样式为一。
4. **预览态单一信号**:全部走 store 的 `preview`,禁止按错误文案匹配。
5. **i18n 基建**:client-nav 全目录无 i18n 层,面向用户文案全硬编码中文(且 ES 侧混入英文)——按 AGENTS.md 约定补齐。
